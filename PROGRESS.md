# DVPN v4 — прогресс реализации

Пошаговый трекер работ по [PLAN.md](PLAN.md). Ссылки `§N` указывают на разделы плана.

**Статус:** `[ ]` не начато · `[~]` в работе · `[x]` готово · `[-]` отложено/не делаем.

**Правила ведения файла:**
- задача считается `[x]` только когда есть код **и** тест (юнит/netns), и `cargo test` + `cargo clippy` чисты;
- в конце каждого этапа выполняется его «Готово, когда» из PLAN.md — отмечается в «Критерий приёмки»;
- при изменении плана синхронизировать и этот файл.

Текущий этап: **Этап 7** (этапы 0–6 закрыты; 3.5 отложен, 3.14, 4.5/4.7, 5.7 — хвосты; ICMP Unreachable/PTB сделаны). Документация — `doc/` (по разделам), README — обзор. Этап 9 (клиенты API) можно вести параллельно 7–8. Версия протокола на проводе: `dvpn/4`, байт версии в handshake-payload с самого начала.

## Этап 5. Mesh-маршрутизация (§6)

- [x] **5.1** `router.rs`: `LsaBody` (origin, group, seq = мс, соседи + cost = RTT), подпись ключом узла, LSDB (новее по seq, срок 120 с от получения, отозванные отбрасываются); без сертификата в LSA (решение этапа 5)

- [x] **5.4** kind 4 `FORWARD` `[limit][hops][probe][dst8][src8][inner]`, сквозные сессии — второй `Links` (тот же psk/сертификаты/отзыв, без своей маскировки), handshake через relay, ответ — по маршруту или назад тем же соседом; пересылают только узлы с ролью relay (`group create/invite --relay`); лимит хопов 16
- [x] **5.5** прямой линк параллельно с relay: link_loop продолжает пробивать прямой путь, пакеты идут напрямую, как только есть живая прямая сессия (сквозная сессия от пути не зависит). Типы NAT в LSA — позже (§6.3)
- [x] **5.6** TTL/Hop Limit (§6.4): источник ставит `limit = min(TTL, 16)` и для TTL ≤ 16 — `probe` + кольцевой буфер (256, 10 с) с цитатой заголовка; relay на исчерпании шлёт kind 5 `REPORT` (маршрутизируется назад к источнику, ≤ 50/с); источник пишет в TUN ICMP Time Exceeded (v4 type 11 / v6 type 3) от overlay-адреса relay (IPv4 из сертификата / ULA); получатель уменьшает TTL на число хопов (RFC 1624)
  - [x] Time Exceeded; Unreachable: relay без пути дальше шлёт REPORT code 1 (traceroute `!H`), источник без адреса и без маршрута до узла сразу отвечает host unreachable, kill switch — admin prohibited; Packet Too Big / Fragmentation Needed: пакет больше пути (прямой 1420, через relay 1368) с DF — ICMP с MTU пути (через relay — от адреса первого relay); netns: kernel запоминает path MTU 1368 через relay, kill switch даёт ICMP вместо тишины
- [~] **5.7** property-тест «нет петель» (router); фаззинг `routing_msg`; разбор FORWARD — в `peer_packet` через link-сессию нет, отдельная цель — вместе с 5.6
