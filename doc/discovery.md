# Обнаружение узлов

[← к содержанию](../README.md#документация)

Чтобы связаться напрямую, узлам нужно узнать внешние адреса друг друга. Для этого есть два способа, их можно
сочетать:

* **серверы обнаружения** (трекеры) — для узлов за NAT;
* **статические узлы** — у которых постоянный адрес.

## Сервер обнаружения

```shell
dvpn server                            # слушает [::]:6485 — IPv6 и IPv4 на одном сокете
dvpn server -a 203.0.113.10 -p 7000    # свой адрес и порт (только этот адрес и его семейство)
```

При первом запуске сервер создаёт ключ Ed25519 и сохраняет его в `config.toml`:

```toml
[local_server]
private_key = "..."    # не передавайте никому
public_key = "..."     # этот ключ указывается у узлов в [servers.*] key
```

Публичный ключ печатается в лог при каждом старте (`Public key: ...`). Если удалить `[local_server]`, будет создан
новый ключ, и его придётся обновить у всех узлов.

Откройте на сервере входящий **UDP**-порт (`ufw allow 6485/udp`).

> Если у сервера **несколько IP-адресов**, запускайте его с `-a <публичный IP>` — тем же адресом, что указан у
> узлов в `[servers.*] addr`. При `::` ядро может ответить с другого адреса, и NAT клиента такой ответ отбросит
> (клиент застрянет в `connecting`).

### Что делает сервер

1. Принимает сессию от узла (Noise IKpsk2; ключ узла доказан рукопожатием — выдать себя за чужой узел нельзя).
2. Принимает **announce** раз в 15 с: сертификат узла и адреса его интерфейсов. Проверяет сертификат по id
   группы — секреты групп серверу не нужны.
3. Отвечает списком участников группы, которые в сети: сертификат, адрес, с которого сервер их видит, и адреса
   интерфейсов. Остальным участникам сообщает о новом узле.
4. Хранит и раздаёт **записи группы** (сертификаты, отзывы, psk для каждого участника в зашифрованном виде, ACL),
   проверяя их подписи. Так записи доходят до узлов, которые были офлайн.
5. Не пускает второй узел по уже использованному invite и исключённые узлы.

Всё хранится только в памяти: клиент, от которого ничего не было 45 с, удаляется. Сессию сервер находит по её
индексу, а не по адресу клиента: если у клиента сменился внешний адрес, сессия продолжается, а участники узнают
новый адрес.

Сервер не участвует в сессиях между узлами и не видит их трафик. Один сервер обслуживает сколько угодно групп.

### Несколько серверов

У узла может быть сколько угодно серверов: `[servers.msk]`, `[servers.am]`, … Узел подключается ко всем сразу и
объединяет их ответы. Админ передаёт свой список в каждом invite.

```toml
[servers.msk]
addr = "msk.example.com"    # IPv4, IPv6 или домен (пробуются все адреса)
port = 6485
key = "..."
```

### Маскировка и зондирование

Сессия с сервером замаскирована так же, как между узлами (ключи маскировки выводятся из публичного ключа
сервера), поэтому по виду пакетов сервер не отличить от участника сети. На случайные пакеты и на повтор
перехваченного рукопожатия сервер не отвечает (рукопожатие несёт метку времени, допустимое расхождение часов —
10 минут), а его ответ никогда не больше запроса — его нельзя использовать для усиления атак.

## Статические узлы

Если у узла постоянный адрес (белый IP или проброшенный порт), к нему можно подключаться напрямую — без сервера
обнаружения. Задайте этому узлу фиксированный порт и укажите адрес при выдаче invite:

```toml
[peer]
bind_port = "7000"
```

```shell
dvpn group invite -n bob --static 203.0.113.10:7000 --static vpn.example.com:7000
```

У Боба появится секция `[[static_peers]]`. Её можно написать и руками:

```toml
[[static_peers]]
key = "DZVSMn8lShIWwhSda4umRbtk027yZh_KeJONsPodlFc"      # ключ узла (dvpn show-key на нём)
endpoints = ["203.0.113.10:7000", "vpn.example.com:7000"]
```

Пока сессии нет, узел шлёт рукопожатие сразу на все адреса (имена разрешаются заново при каждой попытке, IPv4 и
IPv6), увеличивая паузу от 1 с до минуты; ответивший первым адрес используется.

**Сеть совсем без сервера.** Участники подключаются к статическому узлу, а друг о друге узнают через него:
сертификаты и записи группы расходятся между соседями, а [ретрансляция](mesh.md) соединяет тех, кто не видит
друг друга. Если статический узел — ретранслятор, остальным больше ничего не нужно.

## IPv4 и IPv6

Узел работает через один UDP-сокет на оба семейства (`bind_addr = "::"`).

* Серверу узел сообщает адреса своих интерфейсов — **кандидаты**: адреса в локальной сети и IPv6. Сервер
  добавляет адрес, с которого видит узел, и раздаёт этот список участникам.
* Рукопожатие уходит сразу на все адреса собеседника, побеждает первый ответивший. Узлы в одной LAN связываются
  по LAN, а при IPv6 у обоих — напрямую, без NAT.
* Узел без единого IPv4-адреса работает через IPv6 (проверено тестом).
* Адреса внутри сети DVPN кандидатами не бывают — туннель в туннеле не строится.

Адреса интерфейсов видны серверу и участникам группы. `bind_addr = "0.0.0.0"` — только IPv4.

## Порт

```toml
[peer]
bind_port = "8647-9942"     # диапазон: случайный порт из него (по умолчанию)
# bind_port = "7000"        # фиксированный
```

* **Диапазон.** Если все серверы обнаружения стали недоступны, узел переходит на другой случайный порт — это
  помогает, когда NAT или провайдер «залип» на старом.
* **Фиксированный порт** нужен статическому узлу и удобен, если вы пробрасываете его на роутере: тогда узел
  доступен даже собеседнику со строгим NAT.

## NAT

| NAT у узлов | Что будет |
|---|---|
| обычный (full cone, restricted) у обоих | прямая связь через hole punching |
| симметричный у одного | зависит от второго: с full cone или проброшенным портом — прямая связь, с port-restricted — обычно через ретранслятор |
| симметричный у обоих (часто CGNAT, мобильные сети) | прямой путь не пробивается — трафик через [ретранслятор](mesh.md) |
| проброшенный порт у одного | прямая связь с любым |
| оба за одним роутером | по LAN-адресам (кандидатам); через внешний адрес — только при NAT hairpinning |

Пока трафик идёт через ретранслятор, узлы продолжают пробивать прямой путь и переходят на него, как только он
заработал.
