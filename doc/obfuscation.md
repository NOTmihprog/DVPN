# Маскировка трафика

[← к содержанию](../README.md#документация)

Цель — чтобы трафик DVPN не опознавался DPI по сигнатуре, как WireGuard опознаётся по первым байтам и размерам
пакетов. Маскировка включена всегда и не требует настройки.

Это **не** делает DVPN невидимым для анализа потоков (тайминги, объёмы, длительность) и не притворяется
конкретным протоколом для «белых списков» DPI. Она убирает дешёвые способы блокировки по сигнатуре.

## Что видно на проводе

Наблюдатель видит UDP-датаграммы случайного содержимого и случайного размера, не больше 1452 байт.

| Мера | Что даёт |
|---|---|
| **Заголовки зашифрованы** (как в QUIC) | тип пакета, длина заполнения, индексы сессий и счётчик зашифрованы ChaCha20 ключом, выведенным из psk группы; nonce берётся из всегда случайных байт пакета. Без psk не видно даже типа пакета |
| **Случайное заполнение** | к каждому пакету добавляется случайное число байт; длина заполнения аутентифицирована |
| **Ключи рукопожатия неотличимы от случайных** | эфемерный ключ Noise передаётся в виде представления Elligator2 |
| **Мусор перед рукопожатием** | перед каждой инициацией — 4–8 пакетов случайных байт случайного размера |
| **Сигнатурные пакеты** | по шаблону, например имитирующие начало TLS или DNS (синтаксис AmneziaWG `i1`…`i5`) |
| **Таймеры с разбросом** | keepalive, повтор рукопожатий и смена ключей не идут по точному расписанию |
| **Сервер обнаружения не выделяется** | сессия с ним устроена так же, как между узлами |
| **Молчание на зонды** | на случайные пакеты и повторы перехваченных рукопожатий ни узел, ни сервер не отвечают — как закрытый UDP-порт |

Подмена заголовка обнаруживается: изменённый заголовок или длина ломают проверку Noise/AEAD.

## Профиль маскировки

Параметры задаются в `[groups.obfs]`. **Профиль должен быть одинаковым на всех узлах группы**: админ задаёт его
**до выдачи invite**, участники получают его в invite. Если поменять профиль после, уже вошедшие участники с
админом связаться не смогут, пока не получат новый (новый invite или правка их конфига вручную).

```toml
[groups.obfs]
jc = "4-8"        # число мусорных пакетов перед рукопожатием (диапазон "a-b" или число)
jmin = 40         # размер мусорных пакетов, от
jmax = 200        # ... до (не больше 1452)
s1 = "0-96"       # заполнение инициаций рукопожатия, байт
s2 = "0-96"       # ... ответов на рукопожатие
s4 = "0-48"       # ... пакетов данных
i1 = "<b 0x16030301> <r 32> <t>"   # сигнатурные пакеты i1..i5, отправляются перед мусорными
```

Значения выше — значения по умолчанию (сигнатурных пакетов по умолчанию нет). Заполнение — не больше 512 байт и
урезается так, чтобы датаграмма не превышала 1452 байт. Неизвестный параметр — ошибка, а не тихое игнорирование:
опечатка не должна сделать узел непохожим на остальных.

### Шаблоны сигнатурных пакетов

| Тег | Что вставляет |
|---|---|
| `<b 0xHEX>` | фиксированные байты |
| `<r N>` | N случайных байт |
| `<rc N>` | N случайных латинских букв |
| `<rd N>` | N случайных цифр |
| `<t>` | unix-время, 4 байта |

Пакет шаблона не должен быть больше 1452 байт.

Пример — начало TLS ClientHello:

```toml
i1 = "<b 0x160301> <b 0x0200> <b 0x010001fc0303> <r 32> <b 0x20> <r 32>"
```

### Отличия от AmneziaWG

Параметры `h1`…`h4` (заголовки типов) и `s3` не нужны: типы пакетов и так скрыты шифрованием заголовка.
`header_protection` выключить нельзя.

## Цена

Заполнение и мусор стоят трафика: при настройках по умолчанию в среднем ~24 байта на пакет данных и несколько
сотен байт на каждое рукопожатие (раз в ~2 минуты). На скорость шифрования маскировка почти не влияет
([testing.md](testing.md#производительность)).
