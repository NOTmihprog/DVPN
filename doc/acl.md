# Доступ внутри сети (ACL)

[← к содержанию](../README.md#документация)

По умолчанию любой участник может обратиться к любому. Админ может ограничить это правилами — они одинаковы для
всех узлов группы, а соблюдает их каждый узел сам.

## Файл правил

```toml
# acl.toml
default = "allow"                     # или "deny": что не попало ни под одно правило

[tags]                                # группы участников
servers = ["msk-firstvds", "posad"]   # имена участников или ключи
phones = ["phone", "tablet"]

[[rule]]                              # телефоны — только к SSH и вебу серверов
from = ["phones"]                     # теги, участники или "*" (любой участник)
to = ["servers"]
proto = "tcp"                         # tcp, udp, icmp или any (по умолчанию)
ports = ["22", "80-443"]              # порты назначения (для tcp/udp); нет — все порты
action = "allow"

[[rule]]                              # пинговать серверы можно всем
from = ["*"]
to = ["servers"]
proto = "icmp"
action = "allow"

[[rule]]                              # остальное к серверам — нельзя
from = ["*"]
to = ["servers"]
action = "deny"
```

| Поле | Значение |
|---|---|
| `default` | `allow` (по умолчанию) или `deny` — что делать с трафиком, на который не нашлось правила |
| `[tags]` | имя тега → список участников (имена или ключи) |
| `from`, `to` | теги, имена участников, ключи или `"*"` |
| `proto` | `tcp`, `udp`, `icmp` (и ICMPv6) или `any` |
| `ports` | порты или диапазоны назначения: `"22"`, `"8000-8100"` |
| `action` | `allow` или `deny` |

Правила проверяются **по порядку, первое совпадение решает**.

## Команды

```shell
dvpn acl set acl.toml     # проверить файл и сделать его правилами группы (только админ)
dvpn acl show             # текущие правила группы в том же формате
dvpn acl clear            # снять все правила: снова все ко всем (только админ)
```

`acl set` проверяет файл: неизвестные поля, теги и участники, порты без `proto = "tcp"` или `"udp"` — ошибка. Имена
участников при этом заменяются их ключами, так что переименование участника правила не ломает (`acl show`
покажет новые имена). Затем `acl set` записывает правила записью группы,
подписанной её ключом. Работающий узел админа рассылает её за секунды, и каждый узел сразу применяет новые
правила. Подделать или изменить правила может только админ.

## Как правила применяются

Каждый узел применяет правила, в которых он указан в `to`, к трафику **из туннеля к себе и к подсетям за собой**.

* **Кто отправитель** определяется по адресу источника: адреса участника — его IPv4, ULA-адрес и подсети из
  сертификата. Источник подделать нельзя ([проверка источника](routing.md#проверка-источника)), поэтому правило
  по участнику надёжно.
* **Ответы на собственные соединения** узла проходят всегда (conntrack): с `default = "deny"` узел всё равно может
  сам ходить к другим.
* **Трафик не от участников** (интернет через шлюз, публичный IPv6) правила не трогают — для него используйте
  обычный файрвол.
* Если на узел нет ни одного запрещающего правила и `default = "allow"`, узел ничего не ставит.

Реализация — nftables, таблица `inet dvpn_acl` (только Linux):

```shell
nft list table inet dvpn_acl
```

Таблица снимается при остановке узла и при `acl clear`. На Windows и macOS правила пока не применяются.

## Примеры

**Изолированные гости.** Гости видят только медиасервер:

```toml
default = "allow"
[tags]
guests = ["guest1", "guest2"]
[[rule]]
from = ["guests"]
to = ["media"]
proto = "tcp"
ports = ["8096"]
action = "allow"
[[rule]]
from = ["guests"]
to = ["*"]
action = "deny"
```

**Всё запрещено, кроме явно разрешённого:**

```toml
default = "deny"
[[rule]]
from = ["admin-laptop"]
to = ["*"]
action = "allow"
[[rule]]
from = ["*"]
to = ["*"]
proto = "icmp"
action = "allow"
```
