# Группы и участники

[← к содержанию](../README.md#документация)

## Понятия

| Что | Где хранится | Кто видит |
|---|---|---|
| **Ключ узла** (Ed25519) | `[identity] private_key` или `DVPN_PRIVATE_KEY` | публичная часть — все; приватная — только узел |
| **Ключ группы** | публичная часть — id группы (`[[groups]] id`); секрет — `[[groups]] secret` у админа | id — участники и сервер обнаружения |
| **psk группы** | `[[groups]] psk` у участников | только участники |
| **Сертификат** | `[[groups]] cert`, копии у всех участников и у сервера | участники и сервер |
| **Записи группы** | `state.bin` у всех участников и у сервера | участники и сервер |

**Сертификат** — подписанное ключом группы утверждение «узел с таким ключом — участник группы»:

* имя участника (`bob`), по нему его зовут команды и DNS;
* адрес в сети группы (IPv4);
* подсети, которые узел вправе обслуживать (`--route`): LAN за ним, `0.0.0.0/0` для шлюза, публичный IPv6;
* роли: `relay` — ретранслирует трафик других;
* срок действия — 30 дней.

Подделать сертификат нельзя, а значит, и выдать себя за участника, занять чужой адрес или анонсировать чужую
подсеть.

**Записи группы** — тоже подписаны ключом группы: сертификаты, выданные админом; отзывы; новые psk для каждого
участника; правила ACL. Конфликты решаются по времени записи (last writer wins). Записи расходятся по группе
через сервер обнаружения и напрямую между соседями, поэтому доходят и до тех, кто был офлайн.

## Создание группы

```shell
dvpn group create home -n alice -a 10.10.33.1 [--route 192.168.10.0/24] [--relay]
```

* `home` — локальное имя группы (в DNS: `alice.home.dvpn`);
* `-n` — имя этого узла (по умолчанию — начало ключа);
* `-a` — адрес этого узла; маска сети — `[net] mask` (по умолчанию `/24`);
* `--route` — подсеть за этим узлом ([routing.md](routing.md)), можно несколько;
* `--relay` — этот узел ретранслирует ([mesh.md](mesh.md)).

Узел, создавший группу, — её **админ**: у него секрет группы. Без секрета нельзя приглашать, исключать, продлевать
сертификаты, менять psk и ACL. **Сделайте резервную копию сразу** ([ниже](#резервная-копия-админа)).

Пока узел может состоять только в одной группе.

## Приглашение участника

```shell
dvpn group invite -n bob [-a 10.10.33.2] [--ttl 24] [--route 192.168.30.0/24] [--relay] [--static host:port]
```

* `-a` — адрес нового участника; по умолчанию выбирается свободный с учётом всех выданных сертификатов;
* `--ttl` — сколько часов invite действует (по умолчанию 24);
* `--route`, `--relay` — как у `create`, для нового участника;
* `--static` — постоянный адрес этого узла: новый участник подключится к нему напрямую, даже без сервера
  обнаружения ([discovery.md](discovery.md#статические-узлы)). Можно несколько.

Invite — одноразовый пропуск. В нём:

* psk группы и номер его эпохи;
* профиль маскировки ([obfuscation.md](obfuscation.md)) — поэтому профиль нужно задать **до** выдачи invite;
* маска сети группы: `group join` запишет её в `[net] mask` нового узла;
* серверы обнаружения админа и `--static`-адреса;
* одноразовый **ключ входа** и сертификат на него с именем, адресом и ролями нового участника.

Передавайте invite только по защищённому каналу: кто первым войдёт по нему, тот и станет участником.

### Вход

```shell
dvpn group join <invite>          # или -i файл, или без аргумента — вставить в консоль
```

Узел сохраняет группу в `config.toml` и при запуске входит в сеть с сертификатом из invite. Когда работающий узел
админа увидит новичка, он выпустит ему **постоянный сертификат** на его собственный ключ узла и запишет в записи
группы, что invite использован. Второй узел по тому же invite уже не войдёт — сервер обнаружения не пустит его
ещё раньше.

## Делегаты: приглашения в часть сети

Если в группе есть подсети разных команд, админ может разрешить участнику приглашать в его подсеть. Секрета группы
делегат не получает, поэтому такое право можно забрать без пересоздания группы.

```shell
dvpn group delegate add carol --scope 10.10.40.0/24 [--scope ...] [--days 365]   # на узле админа, печатает текст
dvpn group delegate accept <текст>     # на узле делегата; текст — секрет, как invite
dvpn group invite -n phone             # на узле делегата: свободный адрес из его подсети
dvpn group delegate list               # у админа — все делегаты, у делегата — его права
dvpn group delegate remove carol       # на узле админа
```

Делегат только выдаёт invite:

* адрес и `--route` — только внутри `--scope`, это проверяет каждый узел и сервер обнаружения;
* роли давать нельзя: `--relay` откажет;
* исключать, менять участников, psk и ACL может только админ.

`--scope` ограничивает выдачу адресов, а не трафик: новый участник видит всю сеть, как и остальные. Подсети делегатов
не должны пересекаться, а invite админа без `-a` не берут адреса из них.

Обычный сертификат новому узлу выпускает узел админа, как при любом invite, поэтому он должен быть в сети. Если имя
или адрес нового узла уже заняты, узел админа отменяет invite. Срок сертификата из invite не превышает срок делегата.

`delegate remove` отменяет неиспользованные invite этого делегата, а участники, которых он привёл, остаются. Сам
узел делегата тоже остаётся в группе. Чтобы продлить права, удалите делегата и добавьте заново.

Список делегатов хранится в `config.toml` админа и в резервную копию не входит: после `group restore` снять
прежнего делегата командой нельзя, он продолжит работать до конца срока.

## Изменение участника: dvpn node

```shell
dvpn node list                                   # участники: адреса, подсети, роли, срок сертификата
dvpn node set office --add-route 192.168.31.0/24 # ещё одна подсеть за узлом
dvpn node set office --del-route 192.168.30.0/24 # убрать подсеть
dvpn node set phone --addr 10.10.33.40           # новый адрес
dvpn node set phone --add-route 2a01:db8:4:390::7/128   # публичный IPv6 (через шлюз, см. exit.md)
dvpn node set vps2 --relay                       # сделать ретранслятором (--no-relay — снять)
dvpn node set phone --name phone2                # переименовать
```

Участник указывается именем, ключом или однозначным началом ключа. Команда (только у админа) выпускает новый
сертификат и кладёт его в `state.bin`; работающий узел админа за секунды рассылает его через сервер и соседей.
Все участники сразу обновляют маршруты и DNS, а сам участник переносит адреса на своём TUN.

## Исключение участника

```shell
dvpn group members                   # кто вступал: имя, ключ, адрес, срок сертификата или revoked
dvpn group revoke bob [--in 120] [--no-rotate]
```

Отзыв — запись группы. Работающий узел админа подхватывает её за секунду и рассылает. Получив отзыв, участники:

* рвут сессии с исключённым узлом и больше не принимают его рукопожатия;
* убирают его адреса и подсети из маршрутов;
* не пересылают его трафик как ретрансляторы.

Сервер обнаружения убирает его из списка группы.

### Смена psk

Исключённый узел всё ещё знает psk группы: им он может снять маскировку заголовков (но не прочитать трафик —
для сессии нужен действующий сертификат). Поэтому вместе с отзывом админ меняет psk:

1. новый psk шифруется отдельно ключу каждого участника, кроме исключённого, и рассылается записью группы;
2. узлы сразу начинают **принимать** оба psk;
3. через `--in` секунд (по умолчанию 120) все **переходят** на новый psk;
4. старый принимается ещё 10 минут — связь при смене не рвётся.

Участник, который был офлайн всё это время, получит свой новый psk при подключении (записи хранит и сервер), а до
этого останется без связи с остальными.

`--no-rotate` — исключить без смены psk. `dvpn group rotate [--in сек]` — сменить psk без исключения, например,
если invite мог утечь.

## Продление сертификатов

Сертификаты выдаются на 30 дней. Узел админа продлевает их сам, когда до конца срока меньше 10 дней и участник в
сети; участник сохраняет новый сертификат в `config.toml`. Админу достаточно иногда бывать в сети.

Если админа не было больше 20 дней, сертификаты участников начнут истекать, и участники выпадут из группы.
Нужен новый invite: `dvpn group leave home`, затем `dvpn group join`.

## Резервная копия админа

```shell
dvpn group backup -o home.bak        # пароль спросит или возьмёт из DVPN_BACKUP_PASSWORD
dvpn group restore -i home.bak       # на другом узле: он станет админом этой группы
dvpn group restore -i home.bak --with-key   # ... и заберёт ключ прежнего узла админа (заменит его)
```

Файл зашифрован паролем (Argon2id 64 МиБ + XChaCha20-Poly1305) и содержит секрет группы, текущую эпоху psk,
профиль маскировки, серверы обнаружения, статические узлы, сертификат и ключ узла админа. Храните его офлайн.

Без `--with-key` новый узел остаётся со своим ключом и выдаёт себе сертификат с именем, адресом и ролями прежнего
узла админа. Если прежний узел потерян насовсем, исключите его: `dvpn group revoke <старый ключ>`. С `--with-key`
узел становится прежним узлом админа (тот же ключ и сертификат) — тогда прежний запускать нельзя.

Восстанавливать можно только на узле, который ещё не состоит в группе.

## Выход из группы

```shell
dvpn group leave home      # удалить группу из config.toml (у админа — вместе с секретом группы!)
dvpn group list            # группы узла: роль, имя и адрес, срок сертификата
```

## Что видит кто

* **Участники** видят сертификаты всех участников (имена, адреса, подсети, роли), внешние адреса тех, кто в сети,
  и правила ACL.
* **Сервер обнаружения** видит id группы, ключи и сертификаты участников, их внешние адреса и адреса
  интерфейсов, записи группы (кроме psk — они зашифрованы каждому участнику). Трафик он не видит.

Подробнее — [security.md](security.md).
