# Ретрансляторы (mesh)

[← к содержанию](../README.md#документация)

Если два узла не могут связаться напрямую (оба за симметричным NAT, разные сети, фильтры), их трафик идёт через
**ретрансляторы** — участников с ролью `relay`. Обычно это узлы с белым адресом или хорошим каналом.

```
 phone (CGNAT) ──── vps1 (relay) ──── laptop (CGNAT)
                \                   /
                 ── vps2 (relay) ──     путь выбирается по задержке, при падении — другой
```

## Как включить

Роль `relay` записывается в сертификат:

```shell
dvpn group create home --relay          # узел админа ретранслирует
dvpn group invite -n vps2 --relay       # новый участник-ретранслятор
dvpn node set vps1 --relay              # существующий участник (--no-relay — снять)
```

Больше ничего не нужно: пути строятся сами.

## Как это работает

### Link-state

Как OSPF или EasyTier:

1. Каждый узел объявляет своих прямых соседей и задержку (RTT) до них — **LSA**, подписанный ключом узла. В LSA
   не больше 28 самых быстрых соседей, чтобы он помещался в один пакет.
2. LSA расходятся по группе от соседа к соседу. Узел объявляет себя раз в 30 с и при изменении соседей; LSA,
   который не обновлялся 120 с, удаляется.
3. По всем LSA каждый узел считает кратчайшие пути (Дейкстра) и запоминает **первый хоп** к каждому узлу.

Правила:

* **ребро учитывается, только если его объявили оба конца** — нельзя нарисовать себе связь с чужим узлом и
  притянуть его трафик;
* **транзит идёт только через узлы с ролью `relay`**: обычный участник никогда не ретранслирует;
* **гистерезис**: новый путь заменяет текущий, только если он лучше на 10 % и на 5 мс — без «дребезга»;
* исключённые участники выпадают из расчёта сразу.

### Сквозная сессия

Через ретрансляторы идёт **сквозная сессия** между конечными узлами — такая же Noise IKpsk2, как прямая.
Ретранслятор видит только короткие id отправителя и получателя (первые 8 байт ключей) и счётчик хопов, но не
содержимое и не IP-заголовки.

```
DATA(сессия phone↔vps1) [ FORWARD: лимит, хопы, кому=laptop, от=phone [ DATA(сессия phone↔laptop) [ IP ] ] ]
```

* Пути через несколько ретрансляторов поддерживаются (до 16 хопов).
* Если ретранслятор пропал, путь за ~30 с переходит на другой.
* Пока трафик идёт через ретранслятор, узлы продолжают пробивать прямой путь и переходят на него, как только он
  заработал. Сквозная сессия при этом не рвётся.

## Диагностика

```shell
dvpn path laptop      # путь: vps1 -> laptop, или laptop напрямую
dvpn routes           # до каких узлов через кого и с какой стоимостью (мс)
dvpn ping laptop      # 23.40 ms (relays) или (direct)
```

`traceroute` и `tracepath` показывают ретрансляторы как обычные маршрутизаторы, по их адресам в сети группы
(IPv4 из сертификата или ULA):

```
$ tracepath -n 10.10.33.7
 1:  10.10.33.3       8.8ms          ← vps1 (ретранслятор)
 2:  10.10.33.7      21.7ms reached
```

Ретранслятор не видит IP-заголовок, поэтому TTL пакета переносится в заголовок FORWARD (лимит хопов), а ICMP Time
Exceeded от имени ретранслятора формирует узел-источник, когда ретранслятор сообщает ему об исчерпании хопов.

## ICMP и MTU

Узел сам отвечает приложениям ICMP-ошибками за путь, который ядро не видит:

| Ситуация | ICMP | От кого |
|---|---|---|
| хопы кончились на ретрансляторе (traceroute) | Time Exceeded | ретранслятор |
| у ретранслятора нет пути дальше | Host Unreachable (traceroute покажет `!H`) | ретранслятор |
| до узла нет ни пути, ни адреса для попытки | Host Unreachable — сразу, без таймаута | адресат |
| пакет с DF больше пути | Fragmentation Needed (IPv4) / Packet Too Big (IPv6) с MTU пути | первый ретранслятор или адресат |
| kill switch ([exit.md](exit.md#kill-switch)) | Administratively Prohibited | адресат |

**MTU пути.** Прямая сессия несёт IP-пакеты до 1420 байт, путь через ретрансляторы — до 1368 (сквозная сессия
и заголовок FORWARD занимают 52 байта). С MTU туннеля по умолчанию 1350 пакет влезает в любой путь. Если поднять
`[net] mtu`, пакеты больше пути получат ICMP с MTU пути, и система уменьшит их (path MTU discovery). Посмотреть,
что запомнило ядро: `ip route get 10.10.33.7`.

## Защита рассылки

Участник группы может оказаться злонамеренным или сломанным. Против флуда маршрутной информацией и записями
(по образцу gossipsub v1.1):

* **лимит частоты**: LSA одного узла принимается не чаще раза в 2 с; свой узел шлёт при изменениях не чаще раза
  в 4 с;
* **оценка соседей**: за каждое плохое сообщение маршрутизации или записей сосед получает штрафные очки:

  | Сообщение | Очки |
  |---|---|
  | неразборчивое | 10 |
  | невалидное: чужая подпись, другая группа, исключённый узел | 5 |
  | слишком частое | 1 |

  Набрав 50 очков за 60 с, сосед на 5 минут теряет право рассылать маршруты и записи группы (его IP-трафик
  продолжает ходить). В лог пишется предупреждение.
* подписи LSA и записей проверяются у каждого получателя, а старые версии никогда не перезаписывают новые.

## Ограничения

* Ретранслятор несёт трафик других без лимитов скорости — лимиты ретрансляции на соседа в планах (этап 8).
* Ретрансляция через сервер обнаружения (когда в группе нет ни одного ретранслятора) — тоже этап 8.
