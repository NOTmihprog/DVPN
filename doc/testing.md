# Тестирование и производительность

[← к содержанию](../README.md#документация)

```shell
cargo test                                           # юнит- и property-тесты
cargo build && tests/netns-e2e.sh                    # сквозной стенд (без root)
cargo +nightly fuzz run peer_packet                  # фаззинг одной цели
cargo test --release -- --ignored --nocapture bench  # бенчмарк шифрования
```

## Юнит- и property-тесты

`cargo test`, ~130 тестов:

* **криптография**: Noise IKpsk2 сверяется со [snow](https://github.com/mcginty/snow) байт в байт в обеих ролях;
  Elligator2 — с тест-векторами obfs4; окно повторов — с моделью (proptest); смена ключей, роуминг, отказ без psk,
  с чужим psk и без действующего сертификата, повтор рукопожатия;
* **маскировка**: энтропия заголовков, разброс размеров, шаблоны сигнатурных пакетов;
* **группы**: сертификаты и invite (подделка полей, чужой ключ входа), записи (подписи, LWW, синхронизация,
  отзыв, одноразовый invite, psk только участникам); **LWW сходится при любом порядке и дублях доставки**
  (proptest);
* **сервер обнаружения**: маскировка, молчание на зонды и повторы, смена адреса клиента, индекс групп;
* **mesh**: подписи и порядок LSA, двусторонние рёбра, только ретрансляторы в транзите, гистерезис, лимит частоты
  LSA и оценка соседей, свойства путей на случайных графах (proptest);
* **маршруты**: синтаксис CKR, LPM, `inetv4`/`inetv6`, системные маршруты; ACL в nftables; DNS и mDNS; ICMP-ошибки;
  выбор шлюза; конфиг с сохранением комментариев; счётчики.

## Фаззинг

[cargo-fuzz](https://github.com/rust-fuzz/cargo-fuzz), цели в `fuzz/fuzz_targets`:

| Цель | Что |
|---|---|
| `packet_parse` | разбор IP-пакетов |
| `peer_packet` | приём пакетов от узлов: маскировка → рукопожатие / данные |
| `handshake_payload` | payload рукопожатия |
| `obfs_template` | шаблоны сигнатурных пакетов |
| `group_cert` | сертификаты и invite |
| `state_sync` | синхронизация записей группы |
| `routing_msg` | сообщения mesh (LSA) |
| `ckr_spec` | записи CKR |
| `tracker_msg`, `tracker_packet` | сообщения и пакеты сервера обнаружения |

В CI каждая цель гоняется коротко на каждый коммит; длинный прогон — workflow `fuzz-nightly` (вручную).

## Сквозной стенд в network namespaces

`tests/netns-e2e.sh` поднимает сеть из network namespaces с настоящими TUN, NAT и nftables — **без root**, через
`unshare -rnm`. Нужны `unshare`, `ip`, `nft`, `ping`; `tcpdump` и `iperf3` — по желанию.

```
 a 192.168.1.2 ─ nat1 [masquerade + ct new drop] ─┐                ┌─ nat2 [...] ─ b 192.168.2.2
                                         203.0.113.11 ── «интернет» ── 203.0.113.12
                         сервер обнаружения 203.0.113.1:6485, c 203.0.113.20 (белый адрес)
```

A создаёт группу, B и C входят по invite, за A и C — свои LAN. Проверяется:

* сервер не отвечает на случайные пакеты; часы 1970 года; резервная копия админа;
* ping во всех направлениях, прямой путь nat1 → nat2 (hole punching, по счётчику nft), iperf3;
* site-to-site между LAN за A и C; IPv6 внутри сети (ULA);
* выход в интернет через C с переходом на A при недоступности C (оба — `[gateway]`), kill switch с ICMP вместо
  тишины, DNS через шлюз, публичный IPv6 для B через NDP proxy на C;
* отсутствие открытого текста на «интернете», маскировка (нет частого первого байта, ≥ 10 разных размеров на 30
  одинаковых ping);
* замена invite-сертификатов постоянными, `node set` (новая подсеть и адрес доходят до всех), ACL, DNS и mDNS
  по именам, отзыв узла и смена psk без разрыва связи, роуминг при смене внешнего адреса NAT;
* новая группа связывается только по статическому адресу из invite, без сервера; два узла без IPv4 связываются
  по IPv6;
* **mesh**: MA и MC не видят друг друга — связь через ретранслятор MB; `tracepath` (IPv4 и IPv6), `dvpn path`,
  `routes`, `neighbors`, `ping`, `metrics` показывают ретранслятор; path MTU через ретранслятор (1368); падение
  ретранслятора — путь через MD; открытие прямого пути — напрямую; без сервера изменение участника доходит до
  всех через соседей.

Полный прогон занимает несколько минут. При ошибке скрипт печатает `FAIL: …`, хвосты логов узлов и оставляет рабочий каталог.

## CI

Forgejo Actions, `.gitea/workflows/ci.yml`, на каждый push:

| Задача | Что |
|---|---|
| `check` | `cargo fmt --check`, clippy (предупреждения — ошибки), тесты |
| `fuzz` | все цели фаззинга параллельно по 60 с (`tests/fuzz-all.sh`) |
| `netns` | сквозной стенд |

## Производительность

* Сессия Noise с маскировкой — ~88 000 пакетов/с по 1400 байт на ядро (шифрование + расшифровка), не медленнее
  XChaCha20-Poly1305 из 3.x (~85 000 на той же машине).
* iperf3 на netns-стенде — ~300 Мбит/с, упирается в общий процессор стенда.
